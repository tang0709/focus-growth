# Focus & Growth development conventions

- Maintain this repository and the stable Pages URL https://tang0709.github.io/focus-growth/. Update index.html rather than creating versioned HTML copies.
- Read the latest main branch before changing code. Do not force-push or overwrite concurrent changes.
- Core goal: reduce startup friction. Preserve the three-column layout, top long-term project tracking, four state-specific component collections, customizable soft theme, and vertical midnight-to-midnight timeline with plan/actual/compare and calendar views.
- Task completion is manually confirmed. Task elapsed time updates in seconds and supports pause/resume/stop/complete. Computer activity statistics use fixed 10-minute intervals with at least one input event; never equate elapsed time with activity or task completion.
- Preserve localStorage and JSON import/export compatibility. Implement schema migrations for breaking data changes; never silently discard history.
- Global Windows monitoring, system tray, AI API backend, AI planning and direct chat-to-data sync are future features; distinguish working features from placeholders.
- Do not commit actual personal tasks, work records, API keys, backups, or private databases. Use synthetic demo data only. Keep secrets in a local backend, never public JavaScript.
- Test affected functionality and update CHANGELOG.md for each release. Preserve existing features unless the user requests otherwise.
- Sync 0.3 is synthetic-only until separate first-data consent. Do not enable production state.json writes, migrate browser data or deploy an unverified bridge. Keep the original localStorage key unchanged; syncTest=1 uses an isolated test key.
- Never expose the PAT through browser APIs. Preserve explicit Windows pairing, exact loopback Host/Origin, short-lived memory-only sessions, durable unsent queue and field-level conflicts. Never treat empty remote collections as deletion authority.
- V0.3.1 normal-workspace preparation is opt-in and read-only. Keep production writes denied in the native service and transport regardless of pairing or UI flags. No approval-issuing endpoint or unsafe CLI bypass is allowed in preparation releases.
- Keep full browser backups, PRODUCTION-* reports, detailed previews and real data strictly local and outside Git/CI/packages. Show record values only in the encrypted local preview or native dialog; shared reports contain counts/hashes only.
- First real migration needs a second explicit consent tied to a fresh verified backup and current preview digest, local snapshot digest, remote SHA/revision. Changes invalidate approval; do not infer permission from pairing, installation or an empty remote.
- Preserve edits made while a request is pending. Test immutable in-flight operations, durable subsequent edits, offline recovery and acknowledgement rebasing. Do not automatically reschedule or complete past plans.
- Initial migration now has a separate snapshot-bound one-time native entry under windows-sync/first-migration. Preserve all normal production write locks. Its approval authorizes one initialization only, not continuous future writes. Never reuse consumed approval or initialize nonempty/already initialized state.
- The normal page may explicitly read and compare protocol fields after native pairing. Readback must not apply remote data, clear tasks, alter local timing, or silently enable continuous sync. Keep all operation receipts, manifests and personal backups local.

- V0.4 supersedes the earlier synthetic-only implementation restriction only through ContinuousController/ContinuousCloud and a separate device-scoped DPAPI grant. Production pairing remains read-only; a prior initial-migration approval never authorizes ongoing writes. Never issue a real grant or enable production continuous writes without a new explicit user approval.
- Preserve default pause on restart, seven-day grant expiry, native enforcement before each write, fixed canonical target, private identity checks, revision monotonicity, SHA conditions and unique operation IDs. No force flag, grant endpoint or deletion propagation.
- V0.4 test browser key is start-workbench-sync-test-v04; normal start-workbench-v1 is unchanged. Never clone production into a test workspace. Preserve full encrypted checkpoints before incoming changes, local-only fields, stale-tab guards and edits made during backup or pending requests. Running task timers must never be reset by remote completion.
